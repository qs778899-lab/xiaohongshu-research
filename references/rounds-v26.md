# 固定轮次与增量维护（v2.6）

本版接口已通过离线回归及授权账号的局部实测：四组既有搜索取得新增结果，三次普通批次自动接续，同一采集运行复用一个 Node 工作进程。搜索翻至平台末尾、评论附件与视频完整处理、全队列语义核对尚未全部验收；软件发布不等于研究范围完成。

## 建立轮次

沿用现有项目、账号锁及原始资料。先备份 SQLite，配置 `cutoff`（带时区）、`doctors`、`employment_rule`；可用 `task_ids` 限定已有任务，否则固定全部现有任务和搜索排序矩阵。

```bash
python scripts/xhs_project.py --project P round create --id R --config round.json
python scripts/xhs_project.py --project P audit --dry-run --round R
python scripts/xhs_project.py --project P round status --id R
```

独立逐项审计可用 `import-audit --file 已审核清单.json` 导入；保存来源哈希及处理建议，不更改原任务完成状态。

`audit` 写入项目的 `audit-dry-run.json` 并返回分类数量。分类只反映登记状态：已有成果缺回执、遗留核对、执行故障等仍须读原始依据；不能将其当作语义完成。`round status` 提供阶段、缺口及实际运行指标；数量以任务范围为单位，不是患者人数、评论覆盖率或全站召回率。

新候选用 `round enroll --id R --task ID --published-at ISO --basis 来源` 登记。已知晚于截止的内容和不在固定矩阵内的新查询进入 `next_round`；未知日期保留核查。不能删除难翻页的原有查询。子任务按原始来源继承轮次。

## 采集与审读交替

```bash
python scripts/xhs_batch.py --project P work --transport bridge --binding B --round R --units 10
python scripts/xhs_project.py --project P review-next --round R --task TASK --limit 40
python scripts/xhs_bridge.py --project P review --task TASK --receipt receipt.json
```

普通预算和审读交接由当前 Codex 对话继续，不等待用户逐批说“继续”。没有外部后台模型自动读资料。每次最多十个采集单元后，阅读新增文字和所附父楼上下文，再提交实际阅读回执。显式任务清单保留顺序，回复任务优先处理必要的一级评论依赖。默认调度按发现来源轮换医生组；该组只用于分配时间，不能作为评价对象归属证据。

`awaiting_review` 是批量采集的暂停信号，不表示累计未读量。`audit / status / bridge summary` 另给 `pending_review_hash_count`、`pending_review_entity_count` 和 `pending_review_entity_version_count`，从全部累计快照和既有审读版本计算，未索引的新文字也包含在内。较小快照不减少旧待审；相对时间等变化不增加语义版本，但不会自动把新快照标为已读。每次报告内复用来源检查，后次报告重新核对。

已验证的失败截图诊断仅按 `review-next` 的规则排除，不计媒体已读。缺失、篡改或无效来源列入 `pending_review_source_gaps`；`pending_review_entity_counts_complete=false` 时，实体数量只覆盖可核来源，不能把零当作无内容。阶段合计是任务引用量，同帖一级/回复可能重叠，不当独立评论或患者数。批量暂停与这些只读计数分开，不能据报告解除故障或完成范围。

`review-next` 保留来源哈希、原文位置、评论 ID、语义版本及必要上下文。相对时间和点赞变化不产生新语义版本。命令行仅展示一次完整文字、真实回复对象 ID 和必要父楼上下文；不同版本父文不按 ID 强行去重。完整哈希绑定另存原审读包。没有真实 ID 的内容保持来源特定身份；不能按昵称合并。带 `--round` 时，具有绝对带时区发布时间的实体标记本轮或下一轮，日期不明不排除。下一轮内容可以作为理解回复所需上下文，不能计入本轮评价结论。

显式使用同一 `--round` 时，搜索卡可复用已成功提交的卡片文字审读：真实笔记ID、完整已观察文字及作者身份须精确相同，原始文件、原包及归档回执仍有效。完整包保存来源链，简洁输出只减少重复文字。未提交包、不同轮次、非真实ID、内容变更或凭据失效仍重交；只被省略的卡片不能自行成为新的直接审读凭据。新查询的发现来源、归属判断、排序、分页与末尾仍独立核对，卡片已读不提升正文或评论状态。

回执需使用已有 native 规则，并带 `review_packet_id`、`reviewed: true`、实际审读总结及 `bridge_snapshot_hashes`。只读了部分实体包时，快照哈希列表应为空；不能用部分阅读证明整张快照已读。必须读完所有实际未审版本后，才可绑定完整快照。采集停滞不会因审读回执而清零。

## 分页与恢复边界

搜索在可见、尺寸有效的结果区选择实际滚动容器；加载中不滚动或累计停滞，末尾信号只取当前结果区。保存首尾笔记 ID、滚动位置、尺寸、唯一笔记增量；恢复优先使用已保存笔记锚点，像素为后备。连续无进展进入诊断，每个故障周期最多激活、重载各一次。故障隔离后轮换其他可执行任务，不能自动去掉失败记录。

本次运行内复用一个串行 Node 进程；每次操作仍核验账号和目标。自有新建标签的短暂 `about:blank` 只等待加载，已有标签跳出范围仍停止。目标消失仅在精确 ID 探测证明不存在后重建；导航结果不明先核对实际网址，不重发动作。普通首页恢复须有 `--home-restore-authorization` 所引用的已有授权，且身份一致、没有访问警告、租约独占，每个登记目标只恢复一次。验证码、账号限制及未知跳转不适用。

已有公开原帖链接只存在旧 Markdown/文字记录时，先将实际观察的 URL、来源文件和位置整理成 JSON，再用 `xhs_bridge.py --project P attach-source --task ID --file 来源.json` 归档补接。接口只接受原任务精确 ID 的公开网址，仅解除 `OBSERVED_SOURCE_URL_REQUIRED`；原进度、任务状态、其他故障与 STOP 保留。不能根据笔记 ID 编造签名链接。

错误页可用 `xhs_bridge.py --project P diagnose-error --binding B --role detail --file 已保存精确标签元数据.json` 离线诊断。只有错误码、提示和嵌套跳转都精确指向当前导航笔记，才标记 `NOTE_UNAVAILABLE`；这只说明该帖暂时无法浏览。诊断不联网、不改变 STOP、不允许重试，也不能证明账号正常或失效。后续恢复必须另行实际核对授权正常网页上的账号身份，按恢复规则保留原停止凭据。

普通调度仅在一次决策内复用健康状态快照，下一单元重新计算；实际账号租约、STOP和目标核验不使用该缓存。正常返回的 `wall_seconds` 包含初始化、调度、等待、采集和收尾；旧 `metrics.elapsed_seconds` 仍仅为驱动调用时间，不能作为整轮墙钟。提前暂停及异常退出尚未覆盖全程计时。

`audit / status / export` 各自在单次调用内取得一次真实调度健康快照，并复用同次报告的任务行，减少重复全量扫描；下一次调用重新取得，不跨操作缓存。来源哈希、逐项完成凭据及缺口检查仍保留，该快照不授予采集、恢复或解除故障的权限。报告生成耗时与联网采集耗时分别记录，不将报告提速当作检索提速。

深评论需要等待时交接给现有串行调度，保存点击和根分页意图；连续三次真实观察没有新父楼才产生 `COMMENT_PAGINATION_STALLED`。纯等待不增加停滞，停滞不成为末尾，较小快照不覆盖累计内容。该局部缺口及已校验的共享来源会阻止同帖另一阶段重复采集；审读不解除它，不走搜索的激活/重载恢复。只有具体修复后的受限核验及真实新父楼或明确末尾可解除根分页停滞。

评论效率指标从 `metric_scope=project_note_comment_ids_v2` 起，按同一项目、同一笔记的一级评论与回复任务累计真实 ID 的并集计算新增量。同一 ID 的文字变化需审读，但不算新评论；较小快照不减少累计值。旧指标没有此标记，采用早期单任务口径，不与新口径直接合计或比较；两者都不是患者人数或全站覆盖率。

## 媒体与证据

正文轮播按真实序号分批采集到 `media_inventory`，采集与视觉审读分开。回执 `media_reviewed_keys` 绑定本次已读位置及文件哈希；整项完成时也重验以前已审文件，缺图、失效文件、评论附件未核不能完成。视频截图不算看完视频：复用[已有字幕/本地转写流程](media.md)，所有时间段及关键字听校须保留位置和原文件；不可读继续留缺口。评论附件自动打开和视频来源衔接仍待真实验收，不能以正文轮播完成替代。

已被可靠新图替代的旧白图，可按[失败截图的独立诊断](media.md#失败截图的独立诊断)登记诊断确认。它不增加内容或媒体已读、不完成范围；原图、故障及评论附件缺口继续保留，来源失效后恢复待审。

```bash
python scripts/xhs_project.py --project P import-evidence --file 评价逐条出处.json --round R
python scripts/xhs_project.py --project P export --round R
python scripts/xhs_project.py --project P round close --id R
```

导入保留原文哈希归档及历史版本。`--round` 将原有结论里没有任务的旧帖补成待核旧账，不自动完成；显式 `--reviewed` 还要求每条提供 `review_basis`。导入旧结论不会自动核实成人、任职、患者独立性或医生身份。已核变化应更新同一证据 ID，旧版保存在 `evidence_versions`。

导出在 `exports/R/` 生成总文档、成人专项、原帖索引、覆盖与缺口及下轮增量。当前结论来自同一证据源，每条含原帖链接、定位、边界及原始依据；不覆盖旧手工报告。成人已核、现任未核须单列，不误排或误收。`round close` 遇未完任务、无效凭据或未纳入的关联范围会拒绝关闭。

## 交付验收

离线测试不能代替真实原账号验收。至少核对三次连续批次接续、目标医生查询实际进展、评论后排与跨批重排、媒体完整性和统一文档原帖链接，再由独立代理复核。发布前比对原桌面 skill 文件哈希；有其他修改先合并。运行资料、账号绑定、授权、原文及依赖不放入 skill 包。失败原因、未验收功能与剩余范围应出现在交付报告中。
