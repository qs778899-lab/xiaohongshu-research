# 自主运行与故障分流

适用于同一已授权的小红书只读研究任务。目标是减少重复登录、无意义确认和断点后的停顿；不修改 Codex 全局审批配置，也不替用户完成登录验证。

用户选择原 Chrome 的官方扩展时，连接、账号锁、恢复与释放以[固定配置连接](bridge.md)为准；下文 run、凭据清理和 HTTP 超时规则仅用于旧临时会话/API 通道，不能用来要求扩展通道重复登录或禁止已经授权的目标标签操作。

## 入口

先复用已知路径，检查现有项目和指定 run。检查只读本地元数据，不访问小红书、不读取 Cookie 内容、不枚举原 Chrome 窗口；未传 run 时诊断项目队列与项目 STOP，报告会话未选择，不自动查找、选择或创建会话。

```bash
"$XHS_PY" "$XHS_SKILL/scripts/xhs_flow.py" check --project "$XHS_PROJECT" --run "$XHS_RUN"
"$XHS_PY" "$XHS_SKILL/scripts/xhs_batch.py" --project "$XHS_PROJECT" work --run "$XHS_RUN" --units 10 --max-batches 12 --max-seconds 1800
```

`check` 的本地可复用状态不证明在线登录有效。它不触发测试请求，不解除 STOP。实际采集仍逐次检查项目、run 和共享账号的停止标记及锁。

`work` 在有限总预算内接续普通批次，并保持串行、共享账号节奏。达到搜索页组或文字审读阈值时写入 `项目/batch/handoff.json`，交给 **Codex** 阅读原文、筛选主题、核对媒体与归属，再续 `work`。这不是让用户逐条审核。语义判断不会由采集脚本自动通过，不能为了续跑批量伪标已读。总预算用完仍由 Codex 接续；不是研究完成或再次授权点。

## 谁处理下一步

| 状态 | 下一步负责人和动作 |
| --- | --- |
| 普通批次/总预算结束 | Codex 继续同一任务，无需用户确认 |
| 需要审读、筛选、图片/字幕校核 | Codex 读来源并登记依据，再续跑 |
| 一次无 HTTP 响应的合格传输超时 | `work` 冷却后在原 run 自动重试一次；失败保留缺口 |
| 旧字符串 ReadTimeout、可选预热失败、正文读取超时、整体 deadline | Codex 本地诊断，不从错误名称推断账号受限或要求用户扫码 |
| 锁占用、依赖路径失效、普通页面范围变化 | Codex 检查本次进程/路径/已绑定标签；不操作原 Chrome、不盲目重建环境 |
| run 已关闭或已清理 | Codex 确认停止原因、既有授权和依赖；确需新 run 时按运行说明处理，不能继续已清理 run 或为绕过 STOP 自动建新会话 |
| 账号 STOP、未知访问状态 | 停止联网采集，由 Codex 先按访问恢复说明只读诊断；只请求实际缺少的人类操作 |
| 已确认需要登录/验证码 | 保存现场后，一次说明具体操作和所需范围；用户处理后仍需核验恢复，不自动解锁 |
| 工具审批被拒绝 | 不换通道绕过；完成其余工作，向用户说明被拒动作与审批原因 |

不要把所有 `blocked`、`handoff` 或“人工分析”都翻译成询问用户。只有缺少账号选择/授权、用户才能完成登录验证、必须明确的范围变化或系统审批要求时才提问；合并同一原因的问题。继承用户实际授权范围：一次读取不扩大成持续读取，明确的本任务持续恢复授权也不能缩回逐次确认。新授权仍不能覆盖系统当次安装或扩权确认要求。

## 超时与自动重试的精确边界

底层每个 HTTP 请求只有一次发送：connect 10、read 25、write 10、pool 5 秒，主线程整体请求期限 45 秒，不跟随重定向。先接收并检查响应头，再读取正文；收到拒绝/验证/限流状态就停止，不能因正文后续慢而当作无响应超时。整体期限不能保证在已有外部计时器或非主线程中生效时，请求前报错，不静默降级为无限等待。

`work` 仅接受本次 `Project.resume` 写入的结构化 `TransientTransportError`，且限定搜索主接口、正文、一级评论或作者列表的已允许读取。必须没有收到 HTTP 响应、原 run 与任务/页码/游标/payload 一致，项目/run/账号没有 STOP。持久化消耗一次重试额度并至少冷却 15 秒后继续；额度不会随再次调用、程序中断或更换 run 重置。同一请求第二次失败留给 Codex 诊断。

旧错误字符串、响应后读取超时、整体期限、可选预热、浏览器上下文中断、平台错误和未知异常不适用自动重试。失败也记录请求节奏。搜索上游可能包含多个串行预热步骤；45 秒是每次 HTTP 请求的期限，不是整项搜索或浏览器批次的期限。

## 会话和审批

普通批次、审读交接和本地修复期间保留本次临时会话；不为每页、每楼或每次审读重新提取凭据。真实结束、用户中断、确认访问限制后清理；仅剩不可继续的缺口并准备交付时也应结束临时会话，不无限留存凭据。cleanup 后研究队列仍保留。

优先使用已有固定命令和只读诊断入口，避免为每批重写临时联网脚本。需要工具层审批时说明具体命令、目标和本次作用，不申请任意 Python、shell 或原浏览器的宽泛永久许可。系统审批与研究授权分开：skill 不能取消计算机操作、网络或文件权限审批。

`run` 与 `work` 的默认暂停文件都是 `项目/batch/PAUSE`，也可传 `--checkpoint-file`；Ctrl-C 会留下暂停标记，下一次调用不会自动恢复。程序不自动删除暂停文件；用户明确恢复后由 Codex 处理自己的暂停标记。STOP 按访问恢复核查，不能当成普通暂停清除。

## 原生页面读取

通过原生浏览器操作接续时，使用[页面读取与故障定位](ui-readiness.md)。本地 API 环境检查与原生浏览器通道分开判断：系统 Python 缺少依赖不表示 Chrome 无法读取，也不证明原 API 已恢复。
