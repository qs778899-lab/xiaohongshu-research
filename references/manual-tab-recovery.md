# 用户已恢复标签的网页接续

适用于用户已在原授权账号中新开或恢复一个正常小红书标签，并明确要求继续当前研究。保留默认 adapter 采集及全部旧接口；这里新增官方 browser surface 的显式用户标签绑定，不创建或关闭用户标签，不读取 Cookie。

## 验证界面诊断与恢复分开

验证页打不开、旧弹窗消失或用户尚未完成验证时，先用独立入口：

```text
xhs_manual_tab_recovery.py diagnose-active --project P --binding OLD --authorization "实际已有的验证界面诊断授权"
```

此命令只查询原配置当前小红书标签的地址与窗口编号，不绑定标签、不导航、不读取正文、不消耗恢复探针、不解锁采集或发送。它可记录普通采集器正确拒绝的验证码地址；普通页面地址则只表示元数据可见，不能证明弹窗不存在或账号恢复。全部 STOP 和原绑定仍须保持一致。

- `verification_page`：保留实际地址，在原标签展示当前界面供用户处理。不得猜测验证 URL、拼接挑战参数或复制旧二维码。
- `public_page_metadata_only`：通过已授权界面只核对是否有可见验证弹窗。原帖链接不是独立验证入口；弹窗消失时记录“当前未显示，完成状态未知”，不能反复打开同一帖子，也不能重发评论来触发验证。
- `CONNECTOR_PERMISSION_DENIED`：本地连接执行权限问题，不是扩展断线；为同一诊断请求正常执行审批。审批拒绝时保留原因，不换工具执行被拒动作。
- 仅有展示验证界面的授权时，诊断到此结束。用户后来明确要求恢复时保存新的实际指令，另行履行所需恢复审批；不沿用已经被更新的“仅展示”范围，也不把“继续”改写为“已扫码”。若必要验证前提仍未满足，明确报告这项实际前提。

`diagnose-active` 的输出不是 `inspect` 的恢复证明。后者仍需实际恢复信息、同账号检查、一次真实查询、正常正文及审读回执。验证界面由平台提供，工具不能保证已消失的弹窗可重新生成。新出现验证时应及时保存当时的精确标签、实际地址及提示类别，区分独立验证页和原页弹窗；私有证据不进入公共仓库。

## 流程与边界

1. 从已授权的窗口元数据取得精确 tabId、windowId、URL。`inspect` 在操作前后验证该标签、原配置及公开账号 UID；未明确选择标签时不能自动使用浏览器中的第一个页面。
2. 首页仅用于确认身份。`probe-search` 最多打开一个已有查询；`probe-note` 仅打开该真实结果卡片中的一个正常研究帖。原受限帖排除。三步均不等于恢复采集。
3. Codex 实际读完正常帖的标题、正文和作者后，提供带来源哈希的回执，`attest` 建立新的仅网页绑定。原绑定、失败现场和 STOP 原字节保留；API 和媒体下载限制不解除。旧验证码标签不再存在不等于验证码已解决。
4. 同一个用户标签可承担搜索和详情两个角色；两者共享导航状态。后续采集继续使用原账号锁、目标核验、请求间隔和评论分页机制。普通预算或审读交接自动接续。
5. 新访问提示或新 STOP 立即撤销本次网页恢复；不能靠换标签反复尝试。旧受限帖子仍单独列入缺口。当前新标签也不正常时停止联网采集。

命令（路径均为实际归档文件）：

```text
xhs_manual_tab_recovery.py inspect-active --project P --binding OLD --user USER
xhs_manual_tab_recovery.py inspect --project P --binding OLD --metadata META --user USER
xhs_manual_tab_recovery.py probe-search --inspection INSPECTION --task EXISTING_SEARCH_TASK
xhs_manual_tab_recovery.py probe-note --inspection SEARCH_PROBE --url OBSERVED_CARD_URL
xhs_manual_tab_recovery.py attest --probe NOTE_PROBE --review CODEX_REVIEW --binding NEW
xhs_batch.py --project P work --transport bridge --binding NEW --task-list TASKS
```

`USER` 保留用户实际确认与时间，不能编造已解决验证码。回执必须包含实际正文摘要、`/title /body /authors` 位置及捕获哈希；评论、图片不能由这份健康检查回执自动标记已读。

`inspect-active`只查询原配置最近聚焦窗口的当前小红书标签元数据，并归档后走同一复核流程；原`inspect --metadata`接口保留。意外关闭浏览器后，沿用户已授权的配置重新打开，无需退出账号或逐批询问。应用启动成功不代表研究窗口已打开：核对小红书标签元数据，必要时按现有重新打开授权恢复精确窗口，随后重新核验公开账号和正文。原标签确实消失时建立新绑定，不能直接篡改旧绑定的标签ID。

## 新研究项目使用原账号

若账号身份基线保存在另一项目，`inspect` 和 `inspect-active` 可显式传入 `--parent-project SOURCE`，同时以 `--project DESTINATION` 指定新的外部研究目录。原绑定只提供已知配置、公开账号和运行环境；不会复制其可采集状态、标签或恢复凭据。新的搜索任务、正文核验、回执、绑定和后续采集均属于目标项目，仍须重新完成上述实际验证。

同一账号停止状态与标签的一次探针在既有私有账号目录登记消费记录；切换项目不能重试已经失败或结果不明的探针。STOP 原字节不变，仓库内目的地会在浏览器操作前被拒绝。该入口不增加账号、网络或 API 授权。

## 本地错误和接续

正常正文也可作为 `probe-search` 的已核验起点，仍只导航到一个既有查询。若导航已成功且精确页面未变，失败仅为 `BACKGROUND_LAYOUT_UNSETTLED` 或 `CONTENT_LOADING`，在 Codex 实际确认同账号搜索结果恢复显示后，可执行 `finish-search --inspection I --layout-observation OBS`。观察须记录 reader、account_uid、url、observed_at、normal_search_visible、no_access_warning、window_restored 和实际摘要。只读取原页一次，不重放导航；原失败、消费记录和全部 STOP 保留。验证码、账号变化及未知导航不适用。

搜索页末尾斜杠、同一 note ID 的 `/search_result/ID` 与 `/explore/ID` 是等价路径；查询、笔记 ID、账号或验证码路径不同不等价。已保存捕获遇这种本地路径误判时，`finish-search` 只读取已导航页面，`finish-note` 仅验证已保存原文；不重放导航，保留原失败记录。

正常笔记可以没有标题。标题字段明确存在且是空字符串时，健康检查仍要求正文非空、正文阶段及有效公开作者链接，不能以加载中、缺字段或图片占位代替正文。若旧校验已归档 `MANUAL_NOTE_CONTENT_REQUIRED`，且保存的首份正文只有标题为空，可对原 `search-probe.json` 执行 `finish-note --inspection ...`：只核原卡片、导航、页面、账号、正文和冻结 STOP，不调用浏览器，不重放导航或补造标题。原失败和全部来源保留，完成后仍须实际审读正文并 `attest`；动态媒体和评论不会由此记已读。新的访问提示、空正文、错目标或结果不明不适用。

CDP 元数据有时不返回 Chrome 窗口编号，不能用空值覆盖先前已核实的编号。明确返回不同编号仍停止。升级本地验证器后，旧凭据不自动提升为有效：`recheck --project P --binding B` 仅对原来已核实的正常帖做一次只读复核，禁止导航，保留旧凭据；实际阅读新捕获后再 `attest` 到新绑定。账号、标签、会话、排除项或 STOP 改变不能用此路径修复。

这是同账号网页接续能力，不承诺平台末尾、所有评论附件或视频已完成。效果应以真实批次的新增评论、搜索新增 ID 和耗时报告。

### 搜索验证码经用户完成后的原页续读

若已归档的 `probe-search` 精确跳转到验证码页，且其 `redirectPath` 指向原计划查询，用户随后明确确认已完成验证、当前搜索结果已显示，可执行 `resume-verified-search --inspection 原inspection.json --user 新确认.json`。这是独立入口，不扩大 `finish-search` 的本地路径修复条件。

确认保存用户原话、处理时间、原 inspection 指针、账号/context/tab/page 和失败链的哈希指针；时间须晚于原失败。只允许读取同一精确搜索页，不提交导航、不解验证码、不更换账号或标签。原尝试、停止记录和错误均保留，续读在操作前登记一次，失败也不能以新确认反复尝试。结果成功仍为 `collection_permitted=false`，须继续正常帖子探针、Codex实际阅读和 `attest`，才可恢复网页采集。新的验证码、身份或目标变化仍停止。

## 2026-11-11 实测范围

真实同账号新标签完成：读取20张搜索卡片、读到正常正文、续读14条评论；修复窗口编号空值误写后，连续三个普通批次分别处理8、4、6个采集单元，无需用户重新登录或逐批授权。采集后的内容仍由Codex逐项审读，完成与未完成分开记录。

后续搜索曾出现`BACKGROUND_LAYOUT_UNSETTLED`，恢复后的正常前台标签已取得连续两批分页新增；这不解除其他查询的旧故障，也不等于核到平台末尾。用户标签的browser租约不支持owned容器的`tabs/select`，原生标签管理接口也会拒绝改动活跃OpenCLI会话。不得把选择失败当作已前置，不反复调用替代入口。保留故障查询的原断点，继续其他可读任务。

### 已可见的用户标签读取配图

手动绑定标签已经可见时，`xhs_bridge_media.py`先后核对同一账号、笔记、页面和可见状态，使用`verify_visible_user_tab`凭据，无需执行连接器不支持的标签选择。后台或可见性不明时仍保留缺口，不绕过前台要求。原有自有标签的选择流程不变。

导航准备阶段也执行相同边界：如果导航后用户标签处于后台，在提交标签选择前记录局部的`MEDIA_ACTIVATION_UNCONFIRMED`，不将其误报为账号访问限制。该次不读取图片，保留目标核验、原始错误和图片待核项；文字任务仍通过原来的后台文字流程独立核验。验证码、登录等真实访问限制不改写成局部媒体错误。

两个路径都保留截图预热、轮播位置/数量和媒体身份稳定校验，图片实际交给Codex逐张读取；DOM媒体数量和截图成功本身不等于已读。已实测同一正文的5张图片清晰可读；其中模拟外观图与实际治疗照片分别记录。API/CDN下载限制不解除，视频及评论附件仍需各自核查。

对于非预期回首页，先记录实际URL和点击时点，不能仅凭跳转就认定有人操作。静置观察及普通评论批次未复现故障时可报告恢复后的真实进展，同时保留原因未确定和旧现场；不得宣称已经修好未知原因。

已有自主返回授权、原手动绑定的网页凭据仍有效，且搜索或笔记的正文、评论、回复、图片、视频任务在新导航前只做一次元数据核验即因 `UNEXPECTED_TARGET_CHANGE` 停止时，可用 `xhs_manual_home_return.py --project P --binding B return --task TASK --metadata META --failure-log LOG --authorization "实际既有授权依据"`。只接收精确普通首页 `https://www.xiaohongshu.com/explore` 或带唯一参数 `?channel_id=homefeed_recommend` 的推荐首页，不接收 `source=404`、验证码、额外参数、其他页面或未决导航；搜索返回目标仍必须是原 `last_url` 的同账号正常正文归档。核对同一 CDP、原生标签、窗口、账号及 STOP 后只导航一次，原绑定、失败日志、任务断点和消费记录均保存。

作者分页期间意外返回上述首页时，也可使用同一入口。要求原 `last_url` 精确对应该作者任务，失败批次已有成功单元，日志中的单元数、任务、末次快照与队列一致；所有相关快照必须已登记且哈希、同账号及作者页卡片地址有效。恢复到这个已观察作者页，不借此改换作者、标签或账号。返回后实际筛读卡片，并在审核回执中使用 `cards_read=true`、`body_read=false`、`positions=["/cards"]` 及当前 capture 哈希；不把标题阅读记成正文或治疗记录阅读。没有正常历史卡片、分页仍在导航中或恢复结果不明时保留阻塞，不能重复恢复。

从已审读的作者页切到其他正文、一级评论或回复任务之前，若首个单元因目标已变为上述精确首页而停止，也可用同一入口返回原作者页。仅接受 `processed_units=0`、无成功单元及未决导航；调用数为1，或已有自主返回授权时为2（第二次仅为自有标签恢复分支的元数据检查，手动标签在导航前即拒绝）。原 `last_success` 必须是这个作者任务，末次同账号作者快照哈希与全部已采标题审读记录一致。恢复和审核之间冻结该作者的完整任务，包括原分页停滞、exhausted、游标和消费记录；返回只恢复绑定，不续跑被暂停的作者分页，也不直接跳到新任务。额外调用、未审作者原文、作者变更或新增 STOP 都不适用。

返回后捕获原范围，绑定仍为 blocked。Codex 实际读完正文及作者，或作者页的卡片标题后，执行 `xhs_manual_home_return.py --project P --binding B attest --probe PROBE --review REVIEW`；再核对当前原页后仅恢复原绑定 ready，不签发新凭据、不完成研究任务、不解除 STOP。未知结果不重放导航；新的访问限制更新共享 STOP 并使旧凭据失效。此入口不改变 404 恢复语义或原凭据代码指纹。

新建的 manual 网页凭据在首个采集单元前可能没有 `verified_at`；该运行时间戳不是原页验证证明。此时仍由完整的原搜索、正常正文、实际审读及 grant 链核对精确标签、同账号与冻结 STOP 后单次返回。缺少或变更原凭据仍拒绝，不能补造时间戳、改绑定或重复导航来续跑。

## 自主建立新专项标签

已有持续开页授权且原项目网页绑定仍有效时，可运行 `xhs_project_tab.py --project NEW --parent-project OLD --binding ORIGINAL --authorization "实际授权依据"`。它在原配置与精确登记窗口中创建一个固定小红书首页，保留旧标签；先复核原账号及全部 STOP，再对新页执行首页 inspect。随后仍运行 `probe-search / probe-note / attest`，实际读完新搜索和正文才建立新项目绑定。

新建前对既有项目准备记录的检查只证明历史流程完整完成。采集器升级不要求旧完成记录的代码指纹继续等于当前版本，但原始搜索、正常正文、审读回执、账号与标签、文件哈希及全部 STOP 仍须一致。当前父绑定仍必须通过现行授权校验；历史完成证明不能用于实时采集，也不能替代新项目的搜索、正文和回执核验。

准备结果不是恢复凭据。每次创建前记录不可变消费记录；同账号或同 context 任何未完成准备都会阻止新建另一项目来重试。首页成功后仍须同一页面、同一 inspection 链的有效最终 grant 才可进行下一次项目准备。创建结果不明不重复创建，真实访问提示写入共享停止记录。新标签按现有 browser surface 绑定并保留，不自动关闭原用户窗口。此入口不修改旧绑定，不复制采集权限，不读取 Cookie。

已在授权账号完成新页、搜索、正常正文及回执核验；这只验证新项目接入，不表示搜索末尾、全部评论或媒体范围完成。

### 聚焦检查失败后的单次接续

仅当原 `inspection-failure.json` 精确为 `USER_TAB_NOT_FOCUSED`、尚无绑定或身份读取产物时，在原授权窗口实际前置后，可用 `finish-inspection --attempt 原attempt.json` 接续同一次准备。它在任何浏览器操作前独占登记一次接续，复核原始凭据、父绑定、共享账号锁及所有 STOP；原驱动仍检查精确标签、网址、选中窗口和锁定版本。原失败及消费记录保留，不创建新标签、不更换项目或账号。成功只产生 inspection，仍需真实搜索、正常正文与审读核验。任何未知结果、访问限制或已开始绑定均不适用。第二次仍精确为绑定前焦点失败时，普通接续保持拒绝；已完成焦点诊断后可显式运行一次 `finish-inspection --attempt 原attempt.json --verify-focus`。它先只读核对原配置最近聚焦窗口的精确标签，只有原 tabId、windowId、URL、active 全部一致才登记额外一次接续，随后原驱动重新检查焦点并绑定。此前失败、消费记录和全部 STOP 原样保留；此额外接续也不可重放。实时元数据仍不匹配时不执行绑定或导航。

### 已有专项的独立标签重新接续

旧专项的连接失效，但同一配置、同一公开账号已有当前有效的网页绑定时，可给 `xhs_project_tab.py` 增加 `--renew-from-inspection 旧专项已完成的inspection.json`。旧首页、真实搜索、正常正文和实际审读链必须完整，当前父绑定仍须通过现行租约、身份及全部 STOP 核验。旧链仅证明历史流程完成，不授予当前访问权限；当前账号尚未恢复时不能用这个入口换页重试。

重新接续的记录放入旧专项独立的 `bridge/project-tab-renewals/` 目录，保留原连接及所有证据。对同一个旧完成证明只允许一次创建，结果未知或尚未完成新搜索、正文与审读时，不能换参数继续创建。持久化创建意图与账号消费记录共同防止临时目录丢失后重放。新标签仍需完整的 `probe-search / probe-note / attest`，不能直接复制父绑定的采集权限。

若仅临时账号目录中的旧消费记录已被系统清理，独立的历史验证器可检查仍完整的直接搜索、正文、审读、身份、排除项及冻结 STOP 链；缺失必须是精确原账号登记位置，不允许内容被修改或任意文件缺失。这个历史检查只用于重新接续，原实时凭据验证仍要求原消费记录，且新的有效父绑定不可省略。旧链含验证码续读时暂不支持此例外。


### 首次搜索前新首页标签已消失

新专项准备或旧专项重新接续已完成首页身份核验，但 `probe-search` 的第一次元数据检查即报 `TARGET_MISSING`，且没有 `search-before`、导航、搜索捕获或正文探针时，可使用：

```text
xhs_project_tab.py --project P --parent-project SOURCE --binding CURRENT_PARENT --authorization "已有自主恢复授权依据" --replace-missing-before-search ORIGINAL_INSPECTION
```

入口重新核对原准备、共享账号消费记录、冻结 STOP 和当前有效父绑定，并实时检查原精确页面确实不存在。仅连接租约丢失、未知导航、验证码、账号限制、其他页面或已开始搜索都不适用。通过后在同账号已核验窗口只创建一次替代首页；旧标签记录、失败现场和 STOP 保留，原准备通过追加记录连接新检查链。新的首页仍必须完成真实搜索、正常正文和 Codex 审读／`attest`，不能直接开始采集。

创建前同时写入账号与项目的不可变消费记录。创建结果未知、替代页又失联、首页检查失败均不自动再次创建；临时目录清理也不重置次数。其他专项只有这条新链完成后才可继续准备，不能用改名或另建项目绕过。该入口的合成验证不代表真实平台检索已完成。

### 正文导航前页面已变、原搜索页已恢复

`resume-note --inspection 原search-probe.json` 只接续原 `probe-note` 在首个元数据检查报 `MANUAL_PAGE_CHANGED` 的情况：没有导航、正文捕获或后续元数据记录，变更页必须是同次搜索已经观察的正常候选。它保留原尝试、错误和消费记录，在独立子目录只允许一次接续，实时核对原搜索地址、页面和同账号后打开原计划的同一完整卡片链接。原搜索未恢复、验证码、新 STOP、目标变更或未知导航均停止；不能借此改换帖子或重放失败导航。成功仍须实际审读正文并 attest，不完成评论或媒体。

### 已核验用户标签的独立研究标签

当用户标签正文可读，但上游拒绝在该租约中选择标签时，可对当前有效的 manual 网页绑定使用既有 `fork-binding --parent ORIGINAL --binding CHILD --intent STABLE_INTENT --authorization "实际授权依据"`。新标签由本专项创建，原用户标签不选择、不导航、不关闭。父手动恢复凭据、全部 STOP 和原受限笔记清单在每次子租约中重新核对；子标签须实际核对首页 UID，并再次读取真实正文。创建结果不明保留消费记录，不换名字重试。

这不是账号恢复入口：父凭据已过期、出现新 STOP 或账号状态未知时仍拒绝；必须先完成原网页恢复核验。旧 300031 父凭据的派生接口和已保存记录继续有效。

## 新版搜索地址

`/search_result_ai` 仅在精确公开域、单个非空 `keyword` 下可做身份核对与搜索检查；传统搜索与新版搜索不互相冒充相同目标。双重编码的关键词保留原 URL 和实际参数，不重写为推测查询。恢复仍须真实卡片、正常正文、人工审读和新凭据；AI 生成总结不能替代笔记卡片或患者原文，也不能据此确认排序或末尾。若新版页面缺少可核对的真实卡片，保留布局/内容缺口。

标题非空、正文明确为空的图片型笔记，在同账号、精确正文页、有效公开作者和实际笔记图片来源均可核对时，可作为正常页面核验；图片和评论仍保持未读。只有表情资产、加载占位、无作者或异常提示不能通过。若首份捕获仅因此被拒，`finish-note` 可离线复核同一次导航和冻结原文，不重开另一帖、不重试采集；此接续仍需 Codex 实际审读标题、作者及空正文，并完成 `attest`。这份健康检查不证明图片内容或疗效。
