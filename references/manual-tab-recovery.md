# 用户已恢复标签的网页接续

适用于用户已在原授权账号中新开或恢复一个正常小红书标签，并明确要求继续当前研究。保留默认 adapter 采集及全部旧接口；这里新增官方 browser surface 的显式用户标签绑定，不创建或关闭用户标签，不读取 Cookie。

## 流程与边界

1. 从已授权的窗口元数据取得精确 tabId、windowId、URL。`inspect` 在操作前后验证该标签、原配置及公开账号 UID；未明确选择标签时不能自动使用浏览器中的第一个页面。
2. 首页仅用于确认身份。`probe-search` 最多打开一个已有查询；`probe-note` 仅打开该真实结果卡片中的一个正常研究帖。原受限帖排除。三步均不等于恢复采集。
3. Codex 实际读完正常帖的标题、正文和作者后，提供带来源哈希的回执，`attest` 建立新的仅网页绑定。原绑定、失败现场和 STOP 原字节保留；API 和媒体下载限制不解除。旧验证码标签不再存在不等于验证码已解决。
4. 同一个用户标签可承担搜索和详情两个角色；两者共享导航状态。后续采集继续使用原账号锁、目标核验、请求间隔和评论分页机制。普通预算或审读交接自动接续。
5. 新访问提示或新 STOP 立即撤销本次网页恢复；不能靠换标签反复尝试。旧受限帖子仍单独列入缺口。当前新标签也不正常时停止联网采集。

命令（路径均为实际归档文件）：

```text
xhs_manual_tab_recovery.py inspect-active --project P --binding OLD --user USER
xhs_manual_tab_recovery.py inspect --project P --binding OLD --metadata META --user USER
xhs_manual_tab_recovery.py probe-search --inspection INSPECTION --task EXISTING_SEARCH_TASK
xhs_manual_tab_recovery.py probe-note --inspection SEARCH_PROBE --url OBSERVED_CARD_URL
xhs_manual_tab_recovery.py attest --probe NOTE_PROBE --review CODEX_REVIEW --binding NEW
xhs_batch.py --project P work --transport bridge --binding NEW --task-list TASKS
```

`USER` 保留用户实际确认与时间，不能编造已解决验证码。回执必须包含实际正文摘要、`/title /body /authors` 位置及捕获哈希；评论、图片不能由这份健康检查回执自动标记已读。

`inspect-active`只查询原配置最近聚焦窗口的当前小红书标签元数据，并归档后走同一复核流程；原`inspect --metadata`接口保留。意外关闭浏览器后，沿用户已授权的配置重新打开，无需退出账号或逐批询问。应用启动成功不代表研究窗口已打开：核对小红书标签元数据，必要时按现有重新打开授权恢复精确窗口，随后重新核验公开账号和正文。原标签确实消失时建立新绑定，不能直接篡改旧绑定的标签ID。

## 新研究项目使用原账号

若账号身份基线保存在另一项目，`inspect` 和 `inspect-active` 可显式传入 `--parent-project SOURCE`，同时以 `--project DESTINATION` 指定新的外部研究目录。原绑定只提供已知配置、公开账号和运行环境；不会复制其可采集状态、标签或恢复凭据。新的搜索任务、正文核验、回执、绑定和后续采集均属于目标项目，仍须重新完成上述实际验证。

同一账号停止状态与标签的一次探针在既有私有账号目录登记消费记录；切换项目不能重试已经失败或结果不明的探针。STOP 原字节不变，仓库内目的地会在浏览器操作前被拒绝。该入口不增加账号、网络或 API 授权。

## 本地错误和接续

搜索页末尾斜杠、同一 note ID 的 `/search_result/ID` 与 `/explore/ID` 是等价路径；查询、笔记 ID、账号或验证码路径不同不等价。已保存捕获遇这种本地路径误判时，`finish-search` 只读取已导航页面，`finish-note` 仅验证已保存原文；不重放导航，保留原失败记录。

CDP 元数据有时不返回 Chrome 窗口编号，不能用空值覆盖先前已核实的编号。明确返回不同编号仍停止。升级本地验证器后，旧凭据不自动提升为有效：`recheck --project P --binding B` 仅对原来已核实的正常帖做一次只读复核，禁止导航，保留旧凭据；实际阅读新捕获后再 `attest` 到新绑定。账号、标签、会话、排除项或 STOP 改变不能用此路径修复。

这是同账号网页接续能力，不承诺平台末尾、所有评论附件或视频已完成。效果应以真实批次的新增评论、搜索新增 ID 和耗时报告。

## 2026-11-11 实测范围

真实同账号新标签完成：读取20张搜索卡片、读到正常正文、续读14条评论；修复窗口编号空值误写后，连续三个普通批次分别处理8、4、6个采集单元，无需用户重新登录或逐批授权。采集后的内容仍由Codex逐项审读，完成与未完成分开记录。

后续搜索曾出现`BACKGROUND_LAYOUT_UNSETTLED`，恢复后的正常前台标签已取得连续两批分页新增；这不解除其他查询的旧故障，也不等于核到平台末尾。用户标签的browser租约不支持owned容器的`tabs/select`，原生标签管理接口也会拒绝改动活跃OpenCLI会话。不得把选择失败当作已前置，不反复调用替代入口。保留故障查询的原断点，继续其他可读任务。

### 已可见的用户标签读取配图

手动绑定标签已经可见时，`xhs_bridge_media.py`先后核对同一账号、笔记、页面和可见状态，使用`verify_visible_user_tab`凭据，无需执行连接器不支持的标签选择。后台或可见性不明时仍保留缺口，不绕过前台要求。原有自有标签的选择流程不变。

导航准备阶段也执行相同边界：如果导航后用户标签处于后台，在提交标签选择前记录局部的`MEDIA_ACTIVATION_UNCONFIRMED`，不将其误报为账号访问限制。该次不读取图片，保留目标核验、原始错误和图片待核项；文字任务仍通过原来的后台文字流程独立核验。验证码、登录等真实访问限制不改写成局部媒体错误。

两个路径都保留截图预热、轮播位置/数量和媒体身份稳定校验，图片实际交给Codex逐张读取；DOM媒体数量和截图成功本身不等于已读。已实测同一正文的5张图片清晰可读；其中模拟外观图与实际治疗照片分别记录。API/CDN下载限制不解除，视频及评论附件仍需各自核查。

对于非预期回首页，先记录实际URL和点击时点，不能仅凭跳转就认定有人操作。静置观察及普通评论批次未复现故障时可报告恢复后的真实进展，同时保留原因未确定和旧现场；不得宣称已经修好未知原因。
