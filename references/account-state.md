# 持久保存账号保护状态

账号停止记录、公开 UID 关联和一次性探针消费记录应放在仓库外的长期私有目录。旧版本使用系统临时目录；清理后缺失不代表限制解除，也不能据此重放探针。

`defaults.account_state_root` 是 `.local/config.json` 中可选的长期目录映射。配置后目录缺失、权限不安全或是符号链接均拒绝运行，不退回空的临时目录。未配置时保留旧路径兼容；现有账号须先迁移，不能只把映射改成一个空目录。

## 迁移与恢复

先停止当前采集批次，显式选择旧账号状态目录、仓库外目的地及已核实的绑定文件：

```text
xhs_account_state.py migrate --source OLD_STATE --destination DURABLE_STATE --binding-file BINDING_JSON --activate
```

迁移持有原身份锁及所有账号采集锁。保留原目录全部 JSON、账号关联和一次性消费记录；已有 STOP 原字节复制，归档不会覆盖新的停止记录。缺失的 STOP 只有在绑定、原始探针、人工审读和归档链均通过校验时才恢复保护；旧归档重排过 JSON 时必须重建出与原始 SHA256 完全相同的字节。

目的地已存在、归档冲突、原始来源不全或锁占用时拒绝覆盖。复制完成而映射未激活的中断可用下列入口接续；会再次检查源状态和目的地内容，避免丢失中断后新增的停止记录：

```text
xhs_account_state.py activate --destination DURABLE_STATE
```

迁移不恢复采集权限。旧凭据仍指向旧状态位置，必须沿[用户标签接续](manual-tab-recovery.md)重新核对同一公开账号、实际搜索和正常正文，实际审读后生成新绑定。旧代码指纹不再匹配时也执行这一流程，不修改原凭据的指纹，不关闭版本校验。`probe-search` 可从已经核验的首页或正常正文开始，不要求用户手动退回首页；正文加载中、账号变化及原探针已消费仍拒绝导航。恢复只适用于已验证网页，API 和媒体下载限制保留。

恢复后沿原项目任务 ID、分页位置、来源和审读记录续跑。新项目的普通导入不自动继承阅读完成；先核旧原文及回执，再接续缺口。实际验收必须包括真实分页或评论新增、停止进程后同一队列的接续，不能以扩展在线或本地测试代替。

新目录只保存保护元数据，不保存 Cookie。研究正文、图片、实际账号和本机路径均留在外部项目或私有配置，不加入公共测试和提交。
