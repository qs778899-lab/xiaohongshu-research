# 阶段提交与同步

## 触发与阶段边界

每次使用本 skill，包括从其他课题目录调用，都先读仓库根目录的 `AGENTS.md`。如果只检索和整理外部研究数据，不产生代码提交。如果在使用中修复、完善了通用代码、说明或合成测试，则同时承担本次修改的维护收尾。

一个阶段是一组可独立理解、验证和回退的相关改动，例如修复一个分页问题、完成一个配置入口，或明确一项维护规则。阶段验证通过后及时 commit，并按既有授权 push；随后继续原研究任务。不要每次点击或改一行就提交，也不要把已验证的多个阶段积压到整项研究结束。未验证或验证失败的工作不能包装成完成阶段。

## 开始时确认状态

查看 `git status --short`、分支、远程和相对 upstream 的领先/落后情况，记录本次开始前的改动。查看存在的 `.local/maintenance-policy.json` 与 `.local/maintenance-status.json`。策略记录原用户允许的自动提交/推送、精确远程和分支；它不能代替实际用户授权，也不能授权读取凭据或修改 GitHub 权限。

没有 Git 元数据的技能安装包仍可正常检索；如有维护改动，说明当前不能提交，不在未知位置自动初始化或关联远程。已有明确授权且目标一致时不逐批重复询问。原仓库或远程改变时，先核对范围，不能把本地策略机械套到其他克隆。

## 每个阶段执行

1. 审查本阶段 diff；保留其他任务的未提交工作。只显式暂存本阶段的文件或差异，不使用无差别的 `git add .` / `git add -A`。同一文件含来源不明的改动时先分清归属，不替其他任务提交。
2. 按变化做适量验证：说明修改检查链接、技能格式和 diff；行为修改运行对应回归；共享采集、身份、账号锁、隐私或调度逻辑变化时扩展相关测试。只有测试确实运行通过才写通过；跳过与未实测项写清楚。真实验证材料留在仓库外。
3. 新增公共文件先维护 `PUBLIC_FILES.txt`。检查 `git diff --cached --check` 和 `python3 scripts/publication_check.py --staged`，审读暂存 diff。不提交 `.local/`、研究原文、患者信息、会话、个人路径、账号标签或真实访问令牌。
4. 用下面的格式创建一个有意义的提交。提交前检查中途是否出现其他任务的改动。保留 hooks；不修改全局 Git 身份。已经发布的提交不因补充说明而 amend 或改写历史。
5. push 前运行 `python3 scripts/publication_check.py --history`，确认远程/分支属于既有授权范围，并检查远程进展。使用明确的远程与分支，推送本阶段普通提交；不自动创建 release 或移动版本标签。
6. 核对远程分支包含本次提交。远程可以因他人正常提交而领先，不能仅凭不等于本地 HEAD 就判失败，也不能为追求相等覆盖远程。继续下一阶段或原研究任务。

推送只是代码同步，不改变检索任务、账号授权、访问限制或研究完成状态。

## 提交说明

标题使用 `fix:`、`feat:`、`docs:`、`test:` 或 `refactor:` 加具体行为，避免只有“更新”“优化”“完成”等空泛描述。中文或英文均可，措辞朴实，不宣称未经验证的效果。

正文说明问题、最终改动、验证及仍有的限制；根据改动规模写清楚即可，不凑字数。可采用以下结构：

```text
fix: 保留审读交接后的分页停滞状态

原因：交接完成会错误重置采集故障，导致相同页面反复重试。
改动：将采集停滞与审读状态分别维护，只在实际翻页推进后解除停滞。
验证：运行对应分页和审读回归；合成重复页未再被当作推进。
边界：未进行在线账号验证；平台末尾仍需真实末尾信号确认。
```

这是合成示例，不是对当前版本的测试声明。提交消息本身也公开：不写真实课题对象、患者原话、用户名、项目路径或凭据。可使用临时消息文件传给 `git commit -F`，避免 shell 转义破坏多行说明。

## 推送失败与后续恢复

网络错误、认证权限不足、隐私检查失败或远程分歧不得记为已同步。保存本地成果，在 `.local/maintenance-status.json` 记录阶段、提交哈希、目标远程/分支、已做验证、失败原因与下一步；避免记录凭据和原始敏感错误内容。成功后更新或清除对应待同步条目，保留真实状态。

对暂时网络错误先读取远程核对是否实际成功，再做有限重试。远程有新提交时先 fetch 并审查；存在冲突或无法分离其他任务的改动时保留断点，不强推、不重置别人代码、不偷偷变更认证权限。未验证阶段和无法安全完成的同步明确报告，不用等待用户说“继续”来代替可自主完成的步骤。

结束时简要交付：本阶段改动、验证结果、commit 链接或哈希、是否已推送，以及确实尚未完成的项目。没有公共改动时无需制造维护工作。
