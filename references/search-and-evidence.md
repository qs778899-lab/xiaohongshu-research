# 检索与证据规则

## 关键词矩阵

写明目标实体、硬约束、允许关联的历史机构、时间范围与实际问题。负面检索也保留中性和正面结果。

| 组别 | 查询形态 | 目的 |
|---|---|---|
| 直接命名 | 全名＋正畸；全名＋面诊 | 建立明确身份与患者叙述 |
| 部分命名 | 机构＋姓医生；机构＋姓院长；首字母＋正畸 | 捕捉不写全名的表达，允许噪声 |
| 机构场景 | 城市＋机构＋正畸；分院/地址＋牙套 | 找其他主题帖子中的评论 |
| 体验问题 | 全名/机构＋后悔、退费、效果、复发、避雷 | 查负面线索，不预定真实性 |
| 中性经历 | 机构＋复诊、结束、保持器、二次正畸 | 避免仅看到营销或情绪帖 |
| 发现后扩展 | 已观察的旧院名、分院、称呼、相关方案 | 据证据扩展，不臆造别名 |

把约束拆开召回，再逐项复核。结果出现在某搜索词下，不代表满足该词。GT 等缩写可指多个姓名或其他主题；简称查询无效时转到机构和经历场景，不无限堆同义词。

原生 `search_result_ai` 页面可能把真实笔记卡片、点点生成总结和主题筛选词同时显示。只对实际卡片及打开后的原帖记阅读；AI 声称参考若干帖子不等于已发现或已读这些帖子。横向“综合/医生/机构”等词不一定是排序控件，须核对筛选面板的实际选中项。未确认排序时保留“查询结果已观察、排序未核”的单独审计，三排序任务继续待查，不能为方便记账假定 general 已验证。仅为重定位已发现原帖的标题查询与医生覆盖查询分开。

## 候选初筛

卡片筛选只记录实际读到的标题、账号及来源，不能代表正文或评论已读。昵称城市、IP 属地不等于就诊城市；另一位医生姓名不排除比较、转诊或评论入口。标题含糊或医学领域未明确时保留待查，不凭姓名猜专科。明确其他地区的治疗、机构宣传或无关主题可按项目范围排除，并写明具体依据；这仍不证明隐藏评论里没有目标。

复核推翻旧排除时，保留旧审读记录，显式恢复为待采集/待分析；不要只在新说明写“保留”，却让任务仍处于 excluded。较晚来源出现相关线索，也应触发这项重新判断。

## 分页与停止

记录查询、排序、已读页、去重新增数、相关新增数；相关性须语义判断，脚本只算去重新增数。

- 先广度小样本，给有效查询加深页数；重要目标比较综合与最新结果。
- 日期以正文/评论可见时间为准，不能只从 note ID 猜日期。
- 重复页、游标不前进、空数据仍 `has_more=true`，记录异常后停止该分页，不宣称穷尽。
- 验证、限流、访问限制使本次采集停止，不切换工具继续同一访问。
- 用户明确设置的总预算可以形成停止边界。普通批次预算、重复增多或相关新增减少只形成断点或调整优先级；在覆盖优先任务中继续后续页，直到平台明确结束。重复整页、游标停滞等异常单列缺口，不当作完成。
- 原生界面复访时保留每次可见总数及读取时间。总数变化只触发差异核查，不能从差额推断删除或新增了哪些评论；已实际读到的新回复另记来源。父楼删除占位、可读文字、未展开回复分别计数。到达 THE END 后仍与显示总数不符，列出差异及缺失上下文，不把差额补成已读，也不覆盖此前累计成果。报告的完整性限定于该次观察，不能把旧末页标记当成当前实时保证。

这些指标只反映采集范围。本方案没有全站评论全文索引，不能测出真实全站召回率。

## 上下文归因

分别判断“评价是什么”和“评价的是谁”。

1. 保留原帖、父评论、直接回复对象、相邻澄清与作者后续。
2. 区分楼主、评论者、被回复者。“我的医生”不能自动继承原帖中的医生姓名。
3. 跨帖必要时用公开 user ID 或规范公开主页确认同一作者；momo、点号等昵称不够。
4. 核对机构、城市、年份、角色：咨询医生、制定方案者、实际操作者、后续接诊者可能不同。
5. 查看相关图片中的明确线索，不直接合并不同门店和年代。
6. 推断姓名时说明关联链和缺口，不把较可能改成确定。

| 分级 | 依据 | 写法 |
|---|---|---|
| 明确归属 | 自述点名，或原帖及回复关系无歧义 | 明确指向该对象；事件仍是自述 |
| 上下文支持 | 多条身份线索一致，缺关键确认 | 较可能指向；列依据与缺口 |
| 身份不足 | 有经历，人物/机构关联断裂 | 保留线索，不能归给目标 |
| 指向其他对象 | 明确另一个人/机构，或后续澄清 | 不计入目标评价 |

不为分级编概率。是否真实患者、商业关系、医疗因果是独立的不确定项。

## 易错案例（泛化示例）

- A 医生帖下，留言者先赞 A，再抱怨“我的医生做得不好”：负面属于未具名医生，不属于 A。
- 医院投诉下，别人问是否在某专家处维权，当事人说“不是，是保险”：按澄清后的范围判断。
- 帖子写院长，截图显示别的机构：不能按搜索词归入目标。
- 相同矫治方案出现在不同医生病例里：技术相同不建立身份关联。
- 公立医院、医生已退休：可核对时间机构，不能单凭此推定或排除某个人。
- “这不是广告吗”：反映质疑，不证实商业合作或治疗失败。
- “有，不多；二次矫正，之前就有”后接“我也是”：可能承接症状、二次矫正或既有病情，不能推断“在该医生处治疗后严重萎缩”。即使后文确认正在该医生处治疗，仍须另找严重程度与时间因果的证据。
- 平台 AI 助手、百科复述、机构科普：不算独立患者评价。保留 `ai_agent` 等实际身份字段；助手把某新闻、机构或医生关联到楼主经历时，也不能用它补齐归属。须找到当事人的原话或其他直接来源，不能因助手说得具体就把它计作第二位患者或身份确认。
- “猜你想搜”“大家都在搜”、自动补全和推荐标签属于平台导航，不能补全评论中“某医生”的姓名。平台推荐与作者配图姓名不一致时，以作者实际表达分别核对，不把推荐词写入患者原话；同帖比较两位医生时，也要将各自面诊、治疗和评价分开关联。
- 同一缩写在一帖是独立一级评论，在另一帖有真实父评论 ID 并回答“哪家”：后者可补强“作者用此缩写指代机构”的关系，但仍不能自动展开机构全名、分院或医生。新关系写成带来源的后续证据，不能倒改旧楼层关系。

## 广告与独立体验

区分营销信号与已确认商业关系。官方账号、推广标识、导流、模板化夸赞、只有开诊无后续，可降低独立疗效证据权重；仅凭语气不能判假。

时间线、方案变化、复诊细节、长期后续提高信息量，但不保证真实性。不要声称验证过作者没有商业关系。

## 最小证据记录

每条纳入结论的证据记录：note ID、原文链接、读取时间、可见发表时间、必要时公开作者 ID、评论 ID、父评论 ID、直接回复对象、短摘录、上下文摘要、归属分级、关联依据/缺口、商业信号、本帖读取范围。

同一真实评论 ID 的 API 与网页版本字段不完全相同，`documents` 中的最新版本不是全部历史。涉及归属、AI 身份、截断文字或回复对象时，使用只读工具逐来源核对：

```bash
python "$XHS_SKILL/scripts/xhs_context.py" --project "$XHS_PROJECT" --document-id 'comment:已观察帖子ID:已观察评论ID'
```

它按原始快照校验哈希，分别返回每个版本的全文、作者 ID、实际观察到的 AI 标记、父评论及直接回复关系。字段缺失保持未知，不用昵称补 ID；身份或 AI 标记冲突单列。源文件缺失/同源 ID 不唯一显示缺口。只有快照局部身份时拒绝跨来源合并，直接读原始快照。不覆盖数据库，也不因拿到上下文就自动标记已审。

只有昵称的 `reply_to` 要标明；不把它升级为确定用户身份。报告只引用必要短摘录，不复制整个评论区。医疗口碑不替代诊疗判断，不从患者自述直接推定医疗过错。
