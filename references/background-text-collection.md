# 后台文字采集与原标签窗口诊断

此功能用于**已有、已授权的小红书研究绑定**。它把文字采集与视觉核查的前台要求分别处理，沿用原账号、角色标签、会话、账号锁及访问保护。只对指定绑定启用，不更改全局默认配置。

## 明确选择文字模式

在 skill 目录执行以下命令，替换项目绝对路径与已有绑定名：

```sh
python3 scripts/xhs_bridge.py --project "/项目绝对路径" text-mode --binding "已有绑定名" --mode background
python3 scripts/xhs_bridge.py --project "/项目绝对路径" text-mode --binding "已有绑定名" --mode foreground
```

`background`在项目锁、原账号 lease 与既有授权验证通过后，将该绑定的`background_text_collection`设为真正的布尔值`true`；`foreground`将其设为`false`。该命令只保存这一个模式字段，不启动浏览器、采集内容、修改授权或重置进度。旧绑定缺少此字段时继续使用原来的前台行为；字符串`"true"`等其他值不会启用后台模式。

## 后台文字路径

显式启用后，bridge 中的搜索、正文、一级评论、回复及作者历史文字路径可在标签未处于前台时工作。受限的搜索排序、滚动翻页、展开回复等 DOM 交互沿用原实现。正常后台读取不选择标签；只有下述布局恢复允许对原自有标签激活一次，不激活 Chrome 应用或恢复窗口。

后台模式仍核对原角色 lease、CDP page、同账号 UID、已登记 URL／导航意图和查询目标，并保留访问提示、加载状态、真实 DOM 布局与可读内容检查。页面或评论正文没有真正呈现时，继续记为缺口；不能把回复前缀、图片占位或元数据当成完整评论。

该模式通过绑定和具体文字调用共同生效。直接使用独立深读入口`deep.main`仍保留旧行为，不能认为所有深读调用都已切换后台。

## 视觉核查继续使用原前台保护

截图、正文轮播图片、评论图片附件、视频画面及其他视觉核查仍按原来的目标可见性、布局与前台 guard 执行。即使视觉处理器借用`body`任务，也不会因此取得后台文字权限。启用文字后台不代表图片已读，不提高媒体完成数，也不改变现有图片／视频处理流程。

## 只读诊断原研究窗口

```sh
python3 scripts/xhs_bridge.py --project "/项目绝对路径" window-state --binding "已有绑定名" --role search
python3 scripts/xhs_bridge.py --project "/项目绝对路径" window-state --binding "已有绑定名" --role detail
```

诊断先在项目锁和原 lease 内核验已登记目标及账号，再以该标签的**精确 URL**唯一匹配 Chrome tab，读取对应`windows.get(populate:false)`和`tabs.get`，最后重新核验原 page、UID 和 URL。零匹配、多匹配、目标移动或身份变化都会停止，不选择替代窗口。

返回值仅包含原目标标识、前后可见状态、窗口`id/state/focused`和标签`id/windowId/url/active`；不枚举其他窗口，不返回标题，不执行 focus、restore、导航或激活。正常诊断不保存绑定或推进任务；实际访问异常仍沿原`save_failure`及`ACCESS_STOP`边界保留记录。`focused=false`或`visible=false`本身不能证明系统锁屏，也不代表已启用的后台文字必然无法读取。

## 保留断点与故障历史

切换模式不会清除旧`TARGET_NOT_VISIBLE`／`TARGET_VISIBILITY_UNCONFIRMED`记录。只有符合条件、没有待审旧来源的任务，才按**每个采集器代码版本一次**的额度进行受限实采；尝试在采集前登记，失败后不自动重复。取得哈希可核对的实际采集来源并重新确认同账号、同目标后，才能归档对应旧 visibility 故障；新来源继续进入待审，归档不等于研究完成。

分页停滞、评论正文只呈现回复前缀、未读附件、未知身份及其他独立故障不随模式切换消失。若实采发现新评论缺口或停滞，保存新故障，不用旧 visibility 记录遮盖。账号锁、停止文件、验证码、登录失效和访问限制仍按原边界处理，模式命令和只读诊断都不是解除 STOP 的凭据。

## 游标恢复与后台布局

历史游标高水位`cursor`只作为续跑目标；`last_observed_position`记录当前文档实际位置，用于判断这一步是否前进。不能把已经恢复的旧位置当成一次新的翻页，也不能因当前页面高度变小，就把低于历史最高位置的真实前进误计为停滞。恢复位置期间的观察仍保存实际来源，但不增加正式翻页的停滞次数；真正新增笔记或明确末尾信号仍按原规则记录。

旧位置可能超过当前页面可滚动的最大值。发生这种 clamp，或已找回保存的笔记锚点时，记录恢复观察并结束本次位置恢复；**clamp不是平台末尾**，也不删除历史发现结果。正式翻页是否推进仍依据当前实际位置、笔记入口和真实末尾证据判断。

后台卡片出现坐标重叠、堆叠等未稳定布局时，先进行最多3次只读观察。若仍未稳定，只有已登记自有标签、同账号与目标核验均通过时，才保存该角色及精确URL的激活尝试，选择原标签一次，并核实返回的page与不请求窗口焦点。之后仍使用原布局检查，最多再观察3次；失败保持缺口，不重复激活、重载或重选排序。身份、目标及访问异常不进入该恢复。尝试记录跨进程保留，不能通过提交审读清除。

已有故障不会因代码更新消失；按原`verify-local-fix`入口验证实际新笔记、位置推进或明确末尾，再解除对应故障。激活成功本身不构成分页或完成证据。

2026-11-10补验：新查询布局恢复确实执行了一次原搜索标签激活，随后取得27个新笔记ID，实际滚动推进；未取得平台末尾。新增的6项恢复边界测试与原桥接、后台和可见性测试共99项通过。该结果只支持已验证的恢复场景，不承诺所有后台布局都能修复。

**真实最小化、系统锁屏及休眠场景尚未验证，不承诺这些状态下可采集；媒体后台采集也未通过本次验收。** 视觉隔离合同通过，表示截图／附件等继续遵守原前台保护，不表示媒体已能在后台核查。不通过修改可见性返回值或伪造焦点证明成功。

现有单项命令、调度、审读、报告与恢复接口保留；此次功能不改变依赖版本、扩展版本、原登录会话或全局 skill 配置。普通后台采集、inactive 标签和视觉前台路径应分别验收，不能互相代替。
