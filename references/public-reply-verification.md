# 已授权公开问询的发布结果复核

本技能默认只读。此流程仅核对用户已经授权、已经尝试发送的公开回复，不授权发送、补发、私信或关注。

## 验证恢复后优先收尾

点击发送后遇扫码或结果不明时，保留原意图：本人UID、帖子、父楼CID、被回复评论CID及UID、完整文案、点击时间和单次发送记录。出现真实访问限制仍立即停账号；不要用重发触发验证码。

用户完成验证且同账号网页恢复核验通过后，**先复核这些未决问询，再继续扩词检索**。不能把“没有重复发送”作为核验完成条件。

重新进入已观察的原帖，核对精确账号和对象，展开对应父楼全部可读回复，核查本人UID、完整文案及回复关系。若同页仍是发送前旧视图，按已有页面就绪边界作一次普通重载；结果不明不反复重载。沿用账号锁、STOP及页面绑定，不恢复受限API、不改采集故障或旧分页记录。单独保存这次发送后复核的原文和时间，不能把旧END当作这次的当前结果。

结果分开记录：

- `visible_confirmed`：当前原帖中实际看到本人UID、完整问询、正确父楼和回复对象；保存新评论CID及来源。它证明本账号当前视图可见，不证明所有账号均可见，也不证明是哪次点击创建了评论。
- `not_visible_after_complete_check`：发送后新加载原帖，完整阅读目标楼及当前可读评论后未找到。向用户明确说“已完整复核，当前未见发布”，记录核验时间；不能写“确定发送失败”，也不自动补发。
- `verification_incomplete`：卡在验证码、错页、折叠回复、缺失原文或其他具体故障。记录尚差哪一步并优先接续，不能只留下一个笼统“未知”。

显示总数没变、输入框清空、按钮点击返回、扫码完成及昵称相同，均不足以单独确认发布。当前未见可能涉及未提交、审核、隐藏或删除；原因没有证据就不推断。三种结果均保留账号去重记录，不自动恢复发送资格。

## 来源绑定的离线核对器

`xhs_public_reply_check.py --intent I --review R --output O` 只读取本地原文和Codex实际阅读回执，不联网、不发送、不修改问询台账。输出留在仓库外，保留旧核验结果。

意图字段：`note_id / root_comment_id / recipient_comment_id / recipient_uid / recipient_name / account_uid / message / submitted_at`。所有日期带时区。

回执字段：`reader=codex / reviewed=true / account_verified=true / account_uid / note_id / root_comment_id / reviewed_at / summary`，以及`observations`数组中的`file / sha256 / observed_at`。每个来源必须是发送后正确原帖的实际网页评论快照；捕获本身没有身份字段时，由同次实际账号核验和回执绑定，不能编造。只有实际新加载并读完整楼时才声明`fresh_page_loaded=true / target_thread_fully_read=true`。

捕获沿用现有网页格式：`results`中的评论CID、作者公开链接、原文和回复关系；`deepCoverage`中的末尾、楼层及未读项。核对器拒绝哈希变更、发送前来源、错帖或错账号；未读楼和缺失原文不会被提升为完整未见。它核查材料一致性，不能代替实际浏览和阅读。

把复核结论、时间、证据和具体缺口同步回外部台账及报告，替换当前状态的笼统“未知”，保留历史事件。通过测试的核对器不等于两条真实问询已经核验，实际结果须另行完成。
